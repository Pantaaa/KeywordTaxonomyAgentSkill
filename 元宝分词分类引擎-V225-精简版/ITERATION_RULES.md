# 元宝分词分类引擎 - 迭代规则（三维度持续优化）

> **核心原则**：每次分词处理都是迭代机会。处理 → 分析 → 建议 → **用户决策** → 迭代。
> **决策权**：规则完善建议由 Agent 提出，**是否采纳由用户决定**。

---

## 一、迭代流程（每次处理必执行）

```
[1] 处理 ── 用当前规则分类关键词
    ↓
[2] 分析 ── 三维度评估（准确/速度/合规）
    ↓
[3] 建议 ── 输出规则完善建议报告（不直接修改规则）
    ↓
[4] 决策 ── 用户决定采纳/拒绝/部分采纳
    ↓
[5] 迭代 ── 采纳 → 更新规则 → 重新分类 → 验证 → 版本升级
```

---

## 二、三维度评估指标

### 维度 1：分词准确能力（Accuracy）

| 指标 | 定义 | 目标 |
|------|------|:----:|
| **"其他"占比** | 二级标签含"其他"的比例 | < 5% |
| **误分类率** | 抽样检查错误分类比例 | < 2% |
| **词根覆盖率** | 高频词根覆盖"其他"关键词比例 | > 70% |
| **新增二级标签数** | 词根扩展产出的新标签数 | 持续增长 |

**优化手段**：
- 补充分类字典关键词（CAT_PRODUCT/CAT_TEXT 等）
- 调整分类优先级（L1/L2 检测顺序）
- 扩展词根白名单（QUALITY_ROOTS）
- 屏蔽无意义词根（MEANINGLESS_ROOTS）

### 维度 2：处理速度（Speed）

| 指标 | 定义 | 目标 |
|------|------|:----:|
| **吞吐量** | 每秒处理条数（q/s） | > 500 q/s |
| **单文件耗时** | 23 万条文件总耗时 | < 10 min |
| **内存占用** | 流式处理峰值内存 | 不爆内存 |

**优化手段**：
- `re.compile` 全局缓存（V170 实测 3.07× 加速）
- 子分类 pattern 预编译
- 流式读写（read_only + write_only）
- monkey-patch 高频函数（sub_categorize / is_competitor_match）

### 维度 3：规则执行度（Compliance）

| 规则 | 检查项 | 通过标准 |
|------|--------|:--------:|
| **标签格式** | 品牌/竞品/行业-AI/通用四类 | 100% |
| **日期格式** | `年/月/日`（如 26/08/04） | 100% |
| **单元拆分** | 每 5000 条/单元 | 100% |
| **违禁词过滤** | 三层防御命中 | 100% 拦截 |
| **学科知识** | 仅大学及以上学科 | 100% |
| **筛除短词** | 3 字以下（2 字英文保留） | 100% |
| **二级扩展** | 词根 ≥2 字、≥100 次 | 100% |

**验证工具**：
```bash
python test_independent.py    # 22 项引擎自检
python compare_engines.py     # 与完整版对比（差异 < 1%）
python expand_other_v169.py   # 词根扩展验证
```

## 三、规则完善建议报告模板

每次处理完成后，Agent 必须输出以下报告，**等待用户决策**：

```
═══ 分词处理分析报告 ═══

【处理概况】
- 文件: xxx.xlsx（N 条）
- 有效: N 条 | 过滤: N 条 | 耗时: Ns（N q/s）

【维度1 - 准确能力】
- "其他"占比: N%（目标 <5%）
- 发现误分类样本: N 条
  - 样本1: xxx → 当前: A | 应归: B
  - 样本2: xxx → 当前: A | 应归: B
- 可扩展词根: N 个（≥100次）
  - 词根1(次数) / 词根2(次数) / ...

【维度2 - 处理速度】
- 吞吐量: N q/s
- 瓶颈: 描述（如 is_competitor_match 调用过多）
- 优化建议: 描述

【维度3 - 规则执行度】
- 违禁词过滤: N 条 ✅
- 标签格式合规: N% ✅
- 单元拆分: 合规 ✅
- 问题: 描述

【规则完善建议】（待用户决策）
1. [建议] 补充词根"xxx"到 QUALITY_ROOTS（预计覆盖 N 条）
2. [建议] 调整"xxx"分类优先级（预计修正 N 条误分类）
3. [建议] 屏蔽无意义词根"xxx"（避免误扩展）
4. [建议] 优化正则"xxx"（提升速度 N%）

请确认是否采纳：全部采纳 / 部分采纳 / 拒绝
```

## 四、版本迭代触发规则

| 触发条件 | 动作 |
|----------|------|
| 用户采纳 ≥1 条建议 | 更新规则 → 重跑验证 → **升级版本**（upgrade_skill.py 单版本替换） |
| 用户拒绝所有建议 | 不升级，记录到 VERSIONING.md 备注 |
| 用户提出新需求 | 按新需求调整规则 → 升级版本 |
| 发现严重误分类 | 立即修复 → 升级版本 |

**每次版本升级必须记录三维度指标**：

```
V170 (2026-08-05)
- 准确: 其他占比 5.2%→3.1% | 词根覆盖 77%→82%
- 速度: 5929 q/s → 6500 q/s
- 合规: 22/22 自检通过 | 违禁词 100% 拦截
- 采纳建议: #1 补充词根 / #2 调整优先级
```

---

## 五、Agent 行为规范

1. **建议先行，不擅改**：分析后先提建议，用户确认后才修改规则
2. **证据驱动**：每条建议附具体样本/数据（如"xxx 关键词被误归 A，应归 B"）
3. **三维度平衡**：优化准确的同时注意速度和合规，不能顾此失彼
4. **版本留痕**：每个版本记录三维度指标和采纳的建议
5. **回归验证**：任何修改后必须跑 test_independent.py（22/22）+ 对比验证
